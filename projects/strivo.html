Strivo gym management platform

A gym management web app with separate admin and member dashboards, class booking and a membership request workflow, built on React and Supabase.

Overview

Strivo is a project I built to show how a small gym could run its daily operations from one web app. Admins manage trainers, classes and memberships. Members sign in, browse class sessions and book or cancel their place.

It is a portfolio project, not a delivered client engagement.

The business need

Gyms often track classes, trainers, bookings and membership requests in separate places, such as spreadsheets and chat messages. That makes it hard to see who is booked into which class and which membership requests are waiting for a decision.

The solution

One application with two sides. The admin side is where staff manage the gym. The member side is where members book classes and request memberships. Sign-in and role-based access decide which side each person sees.

Membership payments are handled manually outside the app. Strivo records the request and the admin approval.

Technical implementation

  • Front endReact with Vite, React Router for the admin and member routes, and Tailwind CSS for styling.
  • Back endSupabase provides authentication and the Postgres database. There is no custom server.
  • Data modelProfiles link to Supabase users. Bookings link a member to a class session, and classes link to trainers.
  • Data integrityForeign keys with cascading deletes, so removing a user or a class session also removes the bookings tied to it.
  • DeploymentHosted on Vercel.

My role

I built Strivo on my own: the interface, routing, Supabase integration, the database relationships and the deployment.

Challenges and decisions

  • Keeping data consistentI used foreign keys with cascading deletes so bookings never point to a user or session that no longer exists.
  • PaymentsI kept payments outside the app and built a request and approval workflow instead.
